API

Your public address as plain text or JSON. No key, no account, no cookies.

Which address do I get?

The hostname decides the address family. The URL path does not.

What each request returns
Request What you get
https://{{MAIN_HOST}}/api/ip Connection default Returns the family of the connection that reaches the server. On a dual-stack network that is usually IPv6, but the operating system and client decide — curl may pick either.
https://{{V4_HOST}}/api/ip IPv4 only Returns an IPv4 address only. The name has an A record only, so clients without IPv4 cannot reach it, except through NAT64 and DNS64.
https://{{V6_HOST}}/api/ip IPv6 only Returns an IPv6 address only. The name has an AAAA record only, so clients without IPv6 cannot reach it.

The same applies to /api/ip.json: choose a family with the hostname, not with the path.

Quick start

Every client shows the same four requests: plain text, JSON, IPv4 only and IPv6 only. No request needs a key, an account or a special header.

Plain text 
curl -sS https://{{MAIN_HOST}}/api/ip
JSON 
curl -sS https://{{MAIN_HOST}}/api/ip.json
Force IPv4 
curl -sS https://{{V4_HOST}}/api/ip
Force IPv6 
curl -sS https://{{V6_HOST}}/api/ip

Windows PowerShell 5.1: curl is an alias for Invoke-WebRequest. Use curl.exe instead, for example curl.exe -sS https://{{MAIN_HOST}}/api/ip.

Plain text 
Invoke-RestMethod https://{{MAIN_HOST}}/api/ip
JSON 
Invoke-RestMethod https://{{MAIN_HOST}}/api/ip.json
Force IPv4 
Invoke-RestMethod https://{{V4_HOST}}/api/ip
Force IPv6 
Invoke-RestMethod https://{{V6_HOST}}/api/ip

Invoke-RestMethod returns plain text as a string and parses JSON into an object. In Windows PowerShell 5.1, curl is not cURL; curl.exe -sS https://{{MAIN_HOST}}/api/ip calls the real client.

Plain text 
const response = await fetch("https://{{MAIN_HOST}}/api/ip", {
  cache: "no-store",
  credentials: "omit"
});

console.log(await response.text());
JSON 
const response = await fetch("https://{{MAIN_HOST}}/api/ip.json", {
  cache: "no-store",
  credentials: "omit"
});
const data = await response.json();

console.log(data.ip);
Force IPv4 
const response = await fetch("https://{{V4_HOST}}/api/ip", {
  cache: "no-store",
  credentials: "omit"
});

console.log(await response.text());
Force IPv6 
const response = await fetch("https://{{V6_HOST}}/api/ip", {
  cache: "no-store",
  credentials: "omit"
});

console.log(await response.text());

In a browser, these calls are only allowed from https://{{MAIN_HOST}}. The API does not permit other origins. From Node.js or a server there is no such restriction.

Plain text 
import urllib.request

with urllib.request.urlopen("https://{{MAIN_HOST}}/api/ip", timeout=5) as response:
    print(response.read().decode("utf-8").strip())
JSON 
import json
import urllib.request

with urllib.request.urlopen("https://{{MAIN_HOST}}/api/ip.json", timeout=5) as response:
    data = json.load(response)

print(data["ip"])
Force IPv4 
import urllib.request

with urllib.request.urlopen("https://{{V4_HOST}}/api/ip", timeout=5) as response:
    print(response.read().decode("utf-8").strip())
Force IPv6 
import urllib.request

with urllib.request.urlopen("https://{{V6_HOST}}/api/ip", timeout=5) as response:
    print(response.read().decode("utf-8").strip())

The standard library has no per-request family switch. Use the v4. or v6. hostname when you need one family.

Plain text 
wget -qO- https://{{MAIN_HOST}}/api/ip
JSON 
wget -qO- https://{{MAIN_HOST}}/api/ip.json
Force IPv4 
wget -qO- https://{{V4_HOST}}/api/ip
Force IPv6 
wget -qO- https://{{V6_HOST}}/api/ip

-q keeps wget quiet and -O- writes the body to standard output. To pin a family, use the v4. or v6. hostname.

Response formats

Both endpoints return one address in the body. Neither sets a cookie and both send Cache-Control: no-store. Only GET and HEAD are supported; other methods return 405. The examples below use documentation addresses, not real clients.

200Plain text 
203.0.113.42

Content-Type: text/plain; charset=utf-8. The body ends with a single newline, so the next shell prompt starts on its own line.

200JSON 
{"ip":"203.0.113.42","version":4}

Content-Type: application/json; charset=utf-8. version is the address family, 4 or 6.

Errors

An error uses the format of the endpoint you called and never echoes request data — no address, Host header or query string appears in the body.

Error responses
Status and code When
400 invalid_host The Host header is not one of this service's hostnames.
503 ip_unavailable The server could not determine a usable client address.
503 ip_family_mismatch The request arrived on v4. or v6. but the observed address has the other family, for example through a proxy or NAT64.
Plain text 
ip_family_mismatch
JSON 
{"error":"ip_family_mismatch"}

Good to know

A few things the address cannot tell you.

  • A VPN, proxy or carrier-grade NAT can change the address the server observes, so it may not match the one on your router.
  • IPv6 privacy extensions rotate addresses, so two requests from the same device can return different values.
  • A failed check does not prove your ISP has no IPv6. A firewall, VPN or browser policy can block it.
  • On Windows PowerShell 5.1, curl is an alias for Invoke-WebRequest. Use curl.exe for the cURL examples.
  • Browser requests only work from https://{{MAIN_HOST}}. Other websites cannot call the API from JavaScript because no CORS permission is sent to them.
